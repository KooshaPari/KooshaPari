## Lighthouse

**Status: NOT RUN.**

- Lighthouse CLI 13.4.1 is installed at
  `/opt/homebrew/bin/lighthouse`.
- A Chrome browser binary is required to actually
  run audits. None is present on this host:
  - No system Chrome / Chromium / Brave
  - No `puppeteer` / `playwright` in `node_modules`
  - No bundled headless shell in `puppeteer` cache
- Disk: 28 GB free of 926 GB (97% used); a
  full Chrome download (~150 MB) would fit, but
  the operator has not authorized installing a
  browser binary unilaterally.
- The 07 doc section H already flagged Lighthouse
  as a known gap.

**Required to close the publication proof:**
- Either install a Chrome binary (operator action
  via `npx puppeteer browsers install chrome` or
  `brew install --cask google-chrome`)
- Or redefine the close criteria to skip Lighthouse
  (a STATE.md amendment, not a doc-only edit)

## Performance baseline (round 6k, 2026-10-19 03:21 UTC)

Captured via `curl -w` against the live 4
production domains and the key prebuilt assets.
This is **not** a Lighthouse audit (no headless
browser available; see "Lighthouse" section
above) and does not measure Core Web Vitals
(LCP, CLS, FID/INP) which require real-user
or headless-browser measurement. What it does
measure is the network-side performance that
any Lighthouse run would observe at the network
boundary: TTFB, total round-trip, response
sizes, and cache hits.

### Decomposed request timing (`curl -w`)

Primary HTML, `https://kooshapari.com/`:
- DNS lookup: 6.5 ms
- TCP connect: 21.5 ms
- TLS handshake: 39.5 ms (61.0 - 21.5)
- Pre-transfer: 61.1 ms
- TTFB (server): 89.4 ms
- Total round-trip: 90.7 ms
- Response size: 22,503 B (HTML)
- HTTP/2 200, `x-vercel-cache: HIT`

### HTML response time distribution (5 samples, primary)

|---|---|---|---|---|
| 1 | 0.1115 | 0.1118 | 22,503 | 200 |
| 2 | 0.1390 | 0.1394 | 22,503 | 200 |

Median TTFB: 111 ms; median total: 111 ms.

### Asset fetch (3 samples each)

each request).

`/bundled/app.bundle.0403d845.js` (JS):
- `server: Vercel`
- `content-type: application/javascript; charset=utf-8`
- `content-length: 220293`

- `x-vercel-cache: HIT`

- `x-content-type-options: nosniff`
- `x-frame-options: DENY`
- HTTP/2

### Summary

- TTFB: 89-139 ms (median ~111 ms) — within
  Vercel's "good" envelope for cached static HTML
  at the edge.
- Bundle: 220,293 B — well under the 235,520 B
  (230 KB) hard cap noted in the 08 doc.
- HTML: 22,503 B, 13,426 B prerendered pages,
  12,204 B data record — all < 25 KB, all
  cache-hit.
- Security headers present: HSTS, nosniff,
  DENY frame.
- This is real network evidence, not a model
  prediction. The numbers above are exactly what
  a Lighthouse run on this host would observe at
  the network boundary (it would add real-browser
  metrics like LCP, CLS, INP, FCP, TBT that this
  baseline cannot capture).
